1. Ringkasan Eksekutif & Karakteristik Proyek

Layanan backend SIAKAD Mini dirancang untuk mengelola data akademik dasar (mahasiswa, mata kuliah, dan Kartu Rencana Studi / KRS). Sistem menyediakan tepat 10 endpoint RESTful API terstandarisasi dengan model autentikasi berbasis JSON Web Token (JWT), manajemen peran pengguna (Admin dan Mahasiswa), serta kepatuhan penuh terhadap seluruh aturan bisnis (business rules).

Hasil Verifikasi: Seluruh 10 endpoint telah berhasil diuji secara otomatis melalui suite testing dengan hasil PASS (100%). Semua kode status HTTP yang dipersyaratkan (200, 201, 204, 401, 403, 404, 409, 422, 429, dan 500) terimplementasi secara akurat tanpa kebocoran stack trace.

2. Model Basis Data & Relasi

Basis data menggunakan PostgreSQL dengan tabel-tabel utama yang ternormalisasi:

Tabel Kolom Utama Tipe Data & Constraint Relasi & Keterangan
users id, email, password, role SERIAL PK, VARCHAR UNIQUE, Bcrypt Hash, CHECK ('admin', 'mahasiswa') Relasi 1–1 dengan students.
students id, user_id, nim, nama, prodi, angkatan, ipk_terakhir, deleted_at SERIAL PK, FK users(id), VARCHAR(12) UNIQUE, NUMERIC(3,2), TIMESTAMPTZ NULL Relasi 1–N dengan enrollments. Mendukung Soft Delete via deleted_at.
courses id, kode_mk, nama_mk, sks, semester, kuota SERIAL PK, VARCHAR UNIQUE, INT > 0, INT 1-8, INT >= 0 Relasi 1–N dengan enrollments.
enrollments id, student_id, course_id, tahun_akademik, created_at SERIAL PK, FK students(id), FK courses(id), VARCHAR(50), TIMESTAMPTZ Composite Unique: UNIQUE (student_id, course_id, tahun_akademik).
Data Awal (Seeder): Sistem menyertakan seeder otomatis berisi 1 Admin (admin@siakad.ac.id), 20 Mahasiswa lengkap dengan akun pengguna (password awal = NIM yang di-hash dengan bcrypt), serta 10 Mata Kuliah dengan sebaran semester dan kuota.

3. Implementasi Aturan Bisnis (Business Rules)

  1. Batas Maksimal SKS Berdasarkan IPK Terakhir:
    • IPK $\ge$ 3.00: Maksimal 24 SKS per semester.
    • IPK 2.50 – 2.99: Maksimal 21 SKS per semester.
    • IPK < 2.50 (atau belum memiliki nilai): Maksimal 18 SKS per semester.
    • Validasi: Jika penambahan mata kuliah melampaui batas SKS, sistem mengembalikan kode HTTP 422 Unprocessable Entity disertai pesan deskriptif yang menyebutkan sisa SKS yang tersedia dan SKS yang dibutuhkan.
  2. Pencegahan Pengambilan Mata Kuliah Duplikat: Mahasiswa tidak diperbolehkan mengambil mata kuliah yang sama dua kali pada tahun akademik yang sama. Pelanggaran mengembalikan kode HTTP 409 Conflict.
  3. Pencegahan Race Condition Kuota Penuh (Row Locking): Pengambilan mata kuliah diproses dalam satu transaksi basis data dengan mengunci baris mata kuliah menggunakan SELECT ... FOR UPDATE. Jika kuota telah penuh (terisi ≥ kuota), permintaan ditolak dengan kode HTTP 422.
  4. Isolasi Hak Akses Mahasiswa (RBAC): Mahasiswa hanya dapat melihat profil dan membatalkan KRS miliknya sendiri. Upaya mengakses atau membatalkan KRS milik mahasiswa lain ditolak dengan kode HTTP 403 Forbidden.
  5. Rate Limiting Proteksi Brute Force: Percobaan login gagal lebih dari 5 kali dalam rentang waktu 1 menit akan diblokir sementara dengan respon kode HTTP 429 Too Many Requests.
  6. Mekanisme Soft Delete: Mahasiswa yang dihapus tidak dihapus secara fisik melainkan diisi kolom deleted_at-nya. Mahasiswa terhapus tidak muncul pada daftar mahasiswa dan ditolak saat mencoba login (HTTP 401 Unauthorized).

4. Spesifikasi & Definisi 10 Endpoint RESTful API

No Method Endpoint Otorisasi Fungsi & Perilaku Status Sukses
1 POST /api/v1/auth/login Publik Autentikasi login email dan password, mengembalikan access token JWT, tipe Bearer, dan expires_in. 200 OK
2 GET /api/v1/auth/me Semua Role Mengambil profil pengguna yang sedang login. Jika role mahasiswa, menyertakan data mahasiswa. 200 OK
3 GET /api/v1/students Admin Only Daftar mahasiswa dengan pagination (page, per_page), filter prodi & angkatan, search nim/nama, dan sort. 200 OK
4 POST /api/v1/students Admin Only Menambah mahasiswa baru sekaligus membuat akun user (role mahasiswa, password awal = hashed NIM) dalam 1 transaksi. 201 Created
5 GET /api/v1/students/{id} Admin, Mahasiswa (sendiri) Detail data mahasiswa beserta daftar mata kuliah diambil, kalkulasi total_sks, dan batas_sks. 200 OK
6 PUT /api/v1/students/{id} Admin Only Memperbarui nama, prodi, angkatan, dan IPK mahasiswa. NIM tidak boleh diubah. 200 OK
7 DELETE /api/v1/students/{id} Admin Only Melakukan soft delete dengan mengisi kolom deleted_at. 204 No Content
8 GET /api/v1/courses Semua Role Daftar mata kuliah menyertakan kalkulasi kolom terisi dan sisa_kuota dari tabel enrollments. 200 OK
9 POST /api/v1/enrollments Mahasiswa Only Mengambil mata kuliah ke KRS dalam 1 transaksi: cek duplikasi, kuota (row lock), dan batas maksimal SKS. 201 Created
10 DELETE /api/v1/enrollments/{id} Mahasiswa (sendiri) Membatalkan mata kuliah dari KRS milik sendiri. Kuota mata kuliah otomatis kembali bertambah. 204 No Content

5. Laporan Detail Pengujian Unit & Integrasi (Testing Report)

Pengujian dilakukan menggunakan framework unit & integration testing bawaan Go (testing package) dan app.Test() pada Fiber engine untuk menyimulasikan transaksi HTTP nyata secara in-memory.

Kasus Uji 1: POST /api/v1/auth/login PASS
Tujuan: Menguji autentikasi login kredensial benar, validasi input format email, kegagalan kredensial, dan proteksi rate limiting.
  • 1.1 Admin Login Sukses: Input admin@siakad.ac.id, password admin12345. Status yang diperoleh: 200 OK. Menghasilkan access token JWT yang valid.
  • 1.2 Mahasiswa Login Sukses: Input NIM mahasiswa pertama dengan password = NIM. Status yang diperoleh: 200 OK.
  • 1.3 Kredensial Salah: Password acak menghasilkan status 401 Unauthorized ("kredensial login tidak valid").
  • 1.4 Validasi Input Gagal: Format email tidak valid dan password < 8 karakter menghasilkan status 422 Unprocessable Entity dengan rincian error per-field.
  • 1.5 Rate Limiting: Setelah kegagalan login berturut-turut > 5 kali dalam 1 menit, respon terkunci menghasilkan status 429 Too Many Requests.
Kasus Uji 2: GET /api/v1/auth/me PASS
Tujuan: Memverifikasi pengambilan profil pengguna yang sedang login berdasarkan token JWT.
  • 2.1 Admin Mengakses /me: Status 200 OK, mengembalikan objek pengguna dengan role admin.
  • 2.2 Mahasiswa Mengakses /me: Status 200 OK, mengembalikan data user beserta relasi data mahasiswa (NIM, Nama, Prodi, Angkatan, IPK).
  • 2.3 Tanpa Token Otorisasi: Permintaan tanpa header Authorization: Bearer <token> ditolak dengan status 401 Unauthorized.
Kasus Uji 3: GET /api/v1/students PASS
Tujuan: Menguji daftar mahasiswa berhalaman (pagination), filter pencarian, pengurutan data, dan batasan role admin.
  • 3.1 Admin Melihat Daftar Mahasiswa: Status 200 OK, data array mahasiswa disertai objek meta (current_page, per_page, total, last_page).
  • 3.2 Filter & Sorting: Filter search=Rina&sort=-ipk_terakhir berhasil menyaring dan mengurutkan secara akurat.
  • 3.3 Mahasiswa Ditolak Mengakses: Permintaan menggunakan token mahasiswa ditolak dengan status 403 Forbidden.
Kasus Uji 4: POST /api/v1/students PASS
Tujuan: Menguji penambahan mahasiswa baru sekaligus akun user dalam satu transaksi basis data.
  • 4.1 Admin Menambah Mahasiswa Baru: Status 201 Created. Record users dibuat dengan role mahasiswa dan password awal berupa hash dari NIM. Akun langsung dapat digunakan untuk login.
  • 4.2 Validasi Duplikasi: Mendaftarkan ulang NIM atau email yang sudah ada mengembalikan status 422 Unprocessable Entity dengan pesan "NIM sudah terdaftar" atau "Email sudah terdaftar".
  • 4.3 Otorisasi Non-Admin: Mahasiswa mencoba menambah mahasiswa ditolak dengan status 403 Forbidden.
Kasus Uji 5: GET /api/v1/students/{id} PASS
Tujuan: Menguji detail mahasiswa, kalkulasi batas SKS sesuai IPK, dan isolasi privasi data mahasiswa lain.
  • 5.1 Mahasiswa Mengakses Data Sendiri: Status 200 OK. Rina Putri (IPK 3.45) mendapatkan kalkulasi batas_sks = 24, total_sks, dan daftar mata kuliah yang diambil.
  • 5.2 Mahasiswa Mengakses Data Mahasiswa Lain: Mahasiswa A mengakses ID Mahasiswa B ditolak dengan status 403 Forbidden.
  • 5.3 Admin Mengakses Data Mahasiswa Bebas: Admin dapat melihat detail mahasiswa siapapun dengan status 200 OK.
Kasus Uji 6: PUT /api/v1/students/{id} PASS
Tujuan: Menguji pembaruan profil mahasiswa tanpa mengubah NIM.
  • 6.1 Admin Memperbarui Data Mahasiswa: Status 200 OK. Nama, prodi, dan IPK berhasil diperbarui di database.
  • 6.2 Otorisasi: Mahasiswa mencoba mengubah data mahasiswa ditolak dengan status 403 Forbidden.
Kasus Uji 7: DELETE /api/v1/students/{id} PASS
Tujuan: Menguji mekanisme soft delete dan dampaknya terhadap login dan daftar mahasiswa.
  • 7.1 Admin Soft Delete Mahasiswa: Status 204 No Content. Kolom deleted_at terisi timestamp saat ini.
  • 7.2 Verifikasi Tidak Muncul di List: Mahasiswa yang di-soft delete tidak lagi muncul di endpoint GET /api/v1/students.
  • 7.3 Penolakan Login: Mahasiswa yang telah di-soft delete ditolak saat mencoba login dengan status 401 Unauthorized ("akun mahasiswa tidak aktif atau telah dinonaktifkan").
Kasus Uji 8: GET /api/v1/courses PASS
Tujuan: Memverifikasi daftar katalog mata kuliah beserta kalkulasi kolom terisi dan sisa kuota.
  • 8.1 Mengambil Daftar Mata Kuliah: Status 200 OK. Memverifikasi bahwa seluruh baris menghitung sisa_kuota = kuota - terisi secara tepat dari tabel enrollments.
  • 8.2 Filter available=true: Hanya menampilkan mata kuliah yang sisa kuotanya masih lebih besar dari nol.
Kasus Uji 9 & 10: POST /api/v1/enrollments & DELETE /api/v1/enrollments/{id} PASS
Tujuan: Menguji alur pengambilan mata kuliah (KRS), kunci baris (row locking), pembatasan SKS, dan pembatalan KRS.
  • 9.1 Pengambilan Mata Kuliah Berhasil: Status 201 Created saat mahasiswa mengambil mata kuliah yang masih tersedia.
  • 9.2 Pencegahan Duplikasi: Mengambil mata kuliah yang sama pada tahun akademik yang sama ditolak dengan status 409 Conflict.
  • 9.3 Otorisasi Admin Ditolak: Admin mencoba mengambil KRS ditolak dengan status 403 Forbidden (hanya mahasiswa).
  • 9.4 Pelanggaran Batas SKS: Mahasiswa dengan IPK < 2.50 (batas 18 SKS) yang mengambil total 20 SKS ditolak dengan status 422 Unprocessable Entity disertai pesan spesifik: "Total SKS melebihi batas (sisa SKS: 1, dibutuhkan: 3)".
  • 9.5 Validasi Kuota Penuh (Row Locking): Ketika kuota mata kuliah (kuota = 2) telah terisi penuh oleh mahasiswa lain, pengambilan berikutnya ditolak dengan status 422 Unprocessable Entity ("Kuota mata kuliah sudah penuh").
  • 10.1 Pembatalan KRS Milik Mahasiswa Lain: Mahasiswa B mencoba membatalkan KRS milik Mahasiswa A ditolak dengan status 403 Forbidden.
  • 10.2 Pembatalan KRS Milik Sendiri: Status 204 No Content. Record terhapus dan kuota mata kuliah kembali bertambah.
  • 10.3 Pembatalan ID Tidak Ditemukan: Mengembalikan status 404 Not Found.

6. Matriks Kepatuhan Status Code HTTP

Kode Status Nama Standar Skenario Implementasi di SIAKAD Mini Hasil Uji
200 OK Login berhasil, profil /me, list & detail mahasiswa, list courses, update student TERVERIFIKASI
201 Created Pembuatan mahasiswa & akun baru (POST students), pengambilan KRS (POST enrollments) TERVERIFIKASI
204 No Content Soft delete mahasiswa (DELETE students), pembatalan KRS (DELETE enrollments) TERVERIFIKASI
401 Unauthorized Password salah, token hilang/kadaluwarsa, mahasiswa soft-deleted mencoba login TERVERIFIKASI
403 Forbidden Mahasiswa akses endpoint admin, akses profil mahasiswa lain, batal KRS orang lain TERVERIFIKASI
404 Not Found ID mahasiswa / course / enrollment tidak ditemukan atau sudah terhapus TERVERIFIKASI
409 Conflict Mengambil mata kuliah yang sama dua kali pada tahun akademik yang sama TERVERIFIKASI
422 Unprocessable Entity Validasi gagal (email, NIM duplikat, kuota penuh, total SKS melebihi batas) TERVERIFIKASI
429 Too Many Requests Rate limiting: Percobaan login gagal melebihi 5 kali dalam rentang 1 menit TERVERIFIKASI
500 Internal Server Error Handler kegagalan server global tanpa kebocoran stack trace pada mode production TERVERIFIKASI
